# Receipt detail screen

Create `packages/app/features/receipt/__tests__/receipt-screen.spec.ts` and `receipt-screen.visual.spec.ts`; add named shell locators to `utils.ts`. Keep item cards, participant picker/rows, bulk sync button and per-peer debt actions out of these screen-owned interaction assertions and mask their separately tested internals in page screenshots.

- **Owner shell and navigation:** with a deterministic owned receipt, check heading, issued date, rounded sum in its currency, owner avatar, edit/delete controls and the back link. Mock `receipts.getPaged` before following the back link to `/receipts`.
- **Name edit:** opening the pencil shows “Receipt name” and Save in place of the heading. Unchanged save issues no mutation; invalid short name cannot save. Changed valid name calls `receipts.update` with type `name`; pending feedback appears, success updates the heading, and a `TRPCError` rolls back while leaving editing available for retry. Assert query/cache effects and consume expected toasts.
- **Date and currency:** unchanged input/selection do not mutate. Changing date sends type `issued`; changing currency sends type `currencyCode` and updates the displayed symbol/amount. Test pending disabled feedback, failure and retry; use existing currency-picker fixtures rather than repeating its own option screenshots.
- **Removal:** nonempty receipt prompts before `receipts.remove({ id })`; cancel leaves it untouched. Empty receipt deletes directly. During a paused removal, the screen's edit/add controls disable; success redirects to `/receipts` (mock destination list first), and failure restores usable controls on the receipt and reports an error.
- **Guest:** use a foreign `ownerPeerId`, a real self participant and **incoming** debts. Assert no owner-only pencil/delete/sync actions and no owner-only edits. With incoming debt ID and `hasMine: true`, follow `/debts/$id`; with `hasMine: false`, follow `/debts/intentions`; with no ID, the link is absent. Set up each destination's API mocks before clicking.
- **Route failure/fallback:** a failed `receipts.get` shows route-level error UI. Capture the structural heading, date/avatar, amount/participant and three-item skeleton only if a real client transition exposes it: pausing initial SSR-prefetched `receipts.get` hangs the stream.

Capture stable light/dark owner and guest page layouts (including a narrow viewport), a clipped name-edit header and removal dialog. Mask the participant region, item cards and independent sync control; retain shell layout and owner/guest affordances. Capture error/fallback only where reachable. Use named locators, settled peer requests and no leftover toasts.
